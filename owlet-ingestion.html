LEGAL SYSTEM LABS / REPRODUCIBILITY NOTE / v1.1

Owlet / Shenzhen Aoni: source ingestion protocol

This release adds a runnable local workflow for converting a saved SEC exhibit into clause candidates, a source-file hash, and a section-location coverage report.

Acquisition status: incomplete in the build environment. Original SEC HTML bytes were not obtained. No source-file checksum, full-exhibit extraction results, or verified extraction accuracy are claimed on this page.

Source

Official SEC Exhibit 10.11 — Manufacturing and Supply Agreement

Reproducible local workflow

  1. Download or save the original SEC exhibit HTML to your computer.
  2. Place it somewhere accessible locally, e.g. ./owlet-original.html.
  3. From the repository root, run the commands below.
  4. Review output records against original source text before adopting any conclusions.
node packages/sec-ingestion/owlet-pipeline.mjs ./owlet-original.html ./research/sec-contracts/ingested/owlet
node --test tests/*.test.mjs

What is measured

OutputMeaning
source_sha256Identity of bytes in the locally saved input; not proof of SEC authenticity
candidate_countRule-based clause candidates, potentially including TOC duplicates
found / not_foundWhether selected expected section labels appear among candidates
review statusAlways unreviewed until an actual source check is recorded

Selected section-location targets: §§ 2.8, 3.5, 3.6, 3.9, 9.2, 9.3, 11.15 and 11.16. Target selection is drawn from earlier research; it is not an exhaustive gold standard.

Known limitations

HTML section segmentation is heuristic. The source exhibit has internal numbering inconsistencies, and extracted records may conflate table-of-contents entries with operative provisions. This tool does not determine the importer of record, customs liability, indemnity entitlement or arbitral jurisdiction.
